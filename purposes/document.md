# Purpose: Document

**Goal**: Produce formal, publication-ready documentation for the project.

---

## Description

The Document purpose directs the AI agent to produce output that is suitable for formal use — as a reference document, onboarding guide, knowledge base article, or published documentation. The output should be polished, well-structured, and formatted for its intended medium.

When the purpose is Document, the AI agent should prioritize completeness, consistency, and presentation quality. The output should feel like a professional document that could be shared with stakeholders without further editing.

---

## Behavioral Characteristics

- **Polish matters**. Writing should be clean, consistent, and free of grammatical issues.
- **Structured for reference**. Use clear headings, tables of contents, and consistent formatting.
- **Complete and standalone**. The document should not require the reader to reference the source repository.
- **Version-agnostic language**. Avoid words like "currently" or "recently" that date quickly.

---

## Output Modifications

- Include a document title, date, and analysis metadata header.
- Use consistent heading hierarchy throughout.
- Include a table of contents for documents exceeding 500 words.
- Use tables, diagrams, and structured formats to enhance readability.
- Include a "Last Analyzed" timestamp and the analysis level used.
- Format all file paths as inline code for clarity.
- Ensure every section has substantive content — no placeholder text.

---

## Recommended Modes

| Mode | Value |
|------|-------|
| Full Documentation | Complete project reference document |
| Overview | Concise project reference |
| Architecture | Technical architecture document |
| Product | Product specification or brief |
| Progress | Status report or milestone document |
